Option A — reference rides on a study note recommended

  • + A question's text stays a clean deliverable — no reference markup inside it.
  • + Reuses machinery already built — note.mentions.includeForGroup → the export already prints these as support passages.
  • + Includability is kind-aware: study-note (and comment) references can be included; a plain confusion mark stays prep-only.
  • − One extra card to create (a study note) alongside the question.
  • − The link between question and reference is “same anchor,” not visually embedded.

Option B — @-mention inside the question text

  • + Fewer cards — the reference sits visually inside the question it serves.
  • + Matches the Build mock's “Malachi sits under Q2” most directly.
  • − Reference plumbing lives inside the exported question string — the question is no longer plain text.
  • − Reverses the current rule (“a reference lives inside a note, never a question”) — more rework in Write and export.
  • − Mixing an editable mention-chip into the deliverable is fiddlier to get right (and to print cleanly).
